# 《英雄立志传：三国志》动态立绘系统解析报告

> 2026-09-24 · 基于游戏 v1.0.2（2026-09-23 更新）IL2CPP 反汇编 + AssetBundle 解析
> 工具链：Il2CppDumper v6.7.46、UnityPy 1.25.3、capstone 自制 xref 扫描器（tools/ 目录）

---

## 一、结论（TL;DR）

**先前原型（女2动态立绘兼容测试包）纯静态的根本原因：游戏硬编码了"CG 贴图来自模组 bundle 时，一律禁用动态立绘管线，走静态显示"。**

官方更新日志 v1.0.1 原话："对全部2000余个cg全部进行了重制，添加眨眼，呼吸和布料呼吸的效果（这里为了节省内存和硬盘空间没有采用序列帧cg，**但仍支持所有mod中的静态或序列帧头像**）"——后半句的实现在代码里就是一道硬门：只要立绘 Sprite 是从模组 bundle 列表里加载到的，`DynamicCGManager.SetCG(KIKLJDOKOEL)` 直接 `return false`，调用方 UI 回退到老的静态 Image 显示。

所以原型包无论 Data/Eyes/WindMaterial 做得多正确，都不可能动起来——**路线被官方设计堵死，不是资源做得不对**。

## 二、动态立绘系统架构（反汇编还原）

### 2.1 显示入口
59 个 UI 方法（对话、城市信息、武将列表等）显示武将 CG 时：
```
DynamicCGManager.SetCG(hero) 返回 true  → 动态立绘（呼吸+摆动+眨眼）
                  返回 false → 回退传统静态 Image（支持序列帧）
```

### 2.2 SetCG(KIKLJDOKOEL hero) 的三道门（DynamicCGManager$$SetCG @RVA 0x131A080）
```csharp
bool SetCG(KIKLJDOKOEL hero, bool A, bool B) {
    if (!SettingCtrl.<静态字段0x39>) return false;        // 门1：游戏内动态立绘开关
    Sprite sprite = MLGKCIAHBOB.LEOLIJNNIHL(hero, A, out fromMod, out flagB);
    if (fromMod) return false;                            // 门2★：来自模组 → 静态（根因）
    string name = hero.AICIENLMLMB(A);                    // 资源名 = 武将CG名（可被模组重映射）
    return SetCG(name, sprite, flagB, B);                 // 门3：动态管线
}
```

### 2.3 CG Sprite 加载（MLGKCIAHBOB$$LEOLIJNNIHL @0x31A5210）
- 4 个候选路径依次尝试（`Assets/Resource/Image/` 下）：`HeroCG/NewHero/`、`HeroCG/Female/`、`FunctionNPCCG/`、`HeroCG/`，拼 `<前缀><名字>.png`
- 全部经中央加载器 `KEPEAABGLJB.DBMKLOPILCB<T>(path, out fromMod)`
- 开头有名字重映射：静态字典 TryGetValue(hero.HMCJAGPPHBO()) → 模组可把武将指向另一个 CG 名（`replaceCondition` 数据）

### 2.4 中央资源加载器（KEPEAABGLJB$$DBMKLOPILCB @0x3CE53B0）
```
优先级：① 开发工具bundle[0x0] → ② bundle[0x20] → ③ 模组bundle列表（命中则 out fromMod=true）
        → ④ 懒加载基础包（StreamingAssets/AssetBundlesImage/image 等，按需 LoadFromFile）
```
- 模组 bundle 在启动时由 PNCNBABJBJE$$JKDIKEAOMCC 装载：读 `MODs/<模组名>/ModInfo.json` 的 `strIDEnd`，对 7 类文件 `File.Exists` + `LoadFromFile`：
  `AssetBundlesImage/image_<suffix>`、`AssetBundlesAES/sound_`、`AssetBundlesSound/bgmsound_`、`AssetBundlesEquipment/equipment_`、`AssetBundlesBuilding/building_`、`AssetBundlesAES/animation_`、`AssetBundlesAES/effect_`
- `fromMod` 标志只在命中第③层（模组列表）时置 true——这就是 2.2 的门2。

### 2.5 动态管线 SetCG(string name, Sprite) (@0x1319CA0)
```csharp
if (!m_mvvCG.SetData(name) && !force) return false;   // Data JSON 加载+网格映射失败 → 静态
wind = Load<Material>("Assets/Resource/Image/DynamicCG/WindMaterial/"+name+".mat");
if (wind == null) wind = m_matDefault;                 // 风场材质缺省
m_meshRendererCG.sharedMaterial = wind;
// 眼部：
eyeMat = Load<Material>("Assets/Resource/Image/DynamicCG/Eyes"+(old?"Old/":"/")+name+".mat");
if (eyeMat == null) m_meshRendererEyes.enabled = false;        // 无眨眼（身体仍呼吸）
else { m_meshRendererEyes.enabled = true; m_mvvEyes.SetData(name); }
```
注意：**Data/Eyes/WindMaterial 的加载同样走中央加载器（有模组优先），且不检查 fromMod** —— 模组可以给"CG 仍是原画"的角色覆盖动态参数资产。

### 2.6 网格振动（MeshVertexVibration）
- `SetData(name)`：取 DynamicCGManager 预制体 MeshFilter 的网格 → 收集唯一 UV 列表 → 读 `StreamingAssets/VibrationVertexData.json`（全局 609 点网格，全角色共用，勿动）→ 经 `FNNGFEOJIIJ` 加载 `DynamicCG/Data/<name>.json`（`{"sortedWorldPositions":[{x,y,z}×609]}`，JsonUtility 解析）→ 逐顶点把 UV 映射到网格点；映射失败报错 `"顶点{0}的UV({1},{2})无法映射到唯一UV列表"`
- 609 点中 446 点在原点附近（未用点），实际有效点 ~163 个
- `InitDurationAndMulti()`：读 `StreamingAssets/VibrationData.json`（1753 条 `{"name","multi","duration"}`）缓存到静态字典；女2 = multi 0.8 / duration 3.2
- `Update()`：按 multi/duration 做顶点呼吸/摆动动画

### 2.7 .dat 索引格式（AssetBundlesImage/HeroCG.dat 等）
`int32LE 数量 + 重复( byte 长度 + UTF-8 文件名 )` —— 原型猜测的格式是**正确**的。
（游戏本体 HeroCG.dat = 1358 条；另有 HeroCGHalf/HeroIcon/NPCCG 三类；**没有** DynamicCG 索引——动态资产不走 .dat，直接按路径从 bundle 加载）

## 四、做"动态立绘替换"的现实路线

### 路线 A：直接改基础包（唯一能让"换画+全套动态"生效）
用 UnityPy 直接改写 `ThreeKingdom_Data/StreamingAssets/AssetBundlesImage/image`（963MB）：
1. 替换 `herocg/female/<名字>.png`（或对应目录）纹理（新画 1000×1400）
2. 替换 `dynamiccg/eyes/<名字>.png`（眨眼图集 512×512、3×3 帧）+ `.mat`（_Crop* 改成新画眼部绝对像素）
3. 替换 `dynamiccg/windmaterial/<名字>.png`（R/G 遮罩 400×560）+ `.mat`
4. 重拟合 `dynamiccg/data/<名字>.json`（新画人体关键点对应的 609 点世界坐标）
- fromMod=false → 动态管线正常吃你的资产。适合自用/整合包分发（备份原 bundle）
- 工具：UnityPy 已装好；改写时保持 ChunkBasedCompression、版本头不动（只换对象数据可原地改）

### 路线 B：模组内只改"动态参数"（美术图不变）
不覆盖 HeroCG，仅用模组 bundle 覆盖 `DynamicCG/{WindMaterial,Eyes,Data}/<名字>.*`：
- 2.5 节这些加载不检查 fromMod，模组优先级生效
- 可以改：眨眼帧/速度、风场强度/方向/遮罩、网格数据（呼吸幅度）
- 不能改：立绘画作本身（一改 CG 就触发静态门）

### 路线 C：静态替换（已验证可行的模组路线）
TKEditor 导出或 Unity 2021.3.45f2c1 构建：`image_<suffix>` bundle + HeroCG.dat 索引 + ModInfo.json(strIDEnd)。参考已装"原版女将美化GPT版"。

### 路线 D：等待/请求官方
向官方（更新很活跃，两天两版）反馈"动态立绘替换模组支持"需求——代码上只需给 fromMod 门加开关或按"模组同时提供 Data 三件套则放行"的规则。

## 七、后续验证（2026-09-24 补充）：模组实现动态替换的可行通道

### 7.1 门的精确语义（修正"完全不行"的结论）
反汇编复核发现 fromMod 门只拦"**Sprite 命中模组 bundle**"这一种情况：
```
SetCG(KIKLJDOKOEL):
    sprite, fromMod, flagB = LEOLIJNNIHL(hero)     // 4候选路径全找不到 → sprite=null, fromMod=FALSE
    if (fromMod) return false;                     // ★ 只有"在模组里找到了图"才触发
    SetCG(name, sprite, ...)                       // sprite=null 也照样进动态管线！
SetCG(string):
    wind = Load<Material>("DynamicCG/WindMaterial/"+name+".mat"); sharedMaterial = wind;
    if (sprite == null) sprite = LEOLIJNNIHL(name, out);   // 按名补载一次
    if (sprite != null) mat.SetTexture("_MainTex", sprite.texture);  // ★ sprite 为 null 时跳过！
    → CG 网格用风场材质自带的 _MainTex 渲染
```
**只要让"HeroCG 里找不到该名字的 png"，游戏就用模组提供的 WindMaterial 材质里的 _MainTex 当立绘**——换画+动态同时成立。

### 7.2 模组配方（换画 + 全套动态）
1. **改 Hero.json**（TKEditor 导出或手写，模组根目录）：目标武将条目 `icon` 字段改成新名（如 `貂蝉_动态`）。`icon` = CG 资源名（曹操.icon=曹操 ↔ herocg/曹操.png ↔ dynamiccg/data|eyes|windmaterial/曹操.*）
2. **image_<suffix> bundle 内提供**（路径必须是这些）：
   - `dynamiccg/windmaterial/貂蝉_动态.mat`（_MainTex→新立绘纹理，_MaskTex→新 R/G 遮罩）+ `dynamiccg/windmaterial/貂蝉_动态.png`（遮罩 400×560）+ 新立绘主图纹理（放任意非 HeroCG 路径，如 `dynamiccg/windmaterial/貂蝉_动态_art.png`）
   - `dynamiccg/data/貂蝉_动态.json`（609 点网格数据，按新画人体拟合；可先用原版同身材数据）
   - `dynamiccg/eyes/貂蝉_动态.png`（512×512 3×3 眨眼图集）+ `.mat`（_CropX/Y/W/H 用绝对像素）
   - `herocghalf/貂蝉_动态.png`、`heroicon/貂蝉_动态.png`（静态半身/头像，列入 HeroCGHalf.dat/HeroIcon.dat）
3. **绝对不要**在 bundle 里放 `herocg/*/貂蝉_动态.png`——一旦被 Sprite 加载命中模组列表，fromMod=true 前功尽弃
4. shader 问题：原版材质的 shader PPtr 指向游戏 bundle 内编译好的 Shader，模组 bundle 引用不到。两个办法：a) 用 UnityPy 把原版 Shader 对象**移植**进模组 bundle（渲染完全一致，推荐）；b) 按已提取的原版完整属性表自建 shader（原型已有底子，属性名清单见 extracted_original/*.mat.json）
5. `VibrationData.json`（StreamingAssets，模组改不了）没有新名字 → duration/multi 用预制体默认值，幅度主要由材质参数（_WindStrength 等）控制，可接受

### 7.3 不换画只调效果（最简单、零风险）
不动 Hero.json、不放 HeroCG：模组 bundle 直接覆盖 `dynamiccg/{windmaterial,eyes,data}/原名.*` 即可改变原画的眨眼/风场/呼吸（这些加载不检查 fromMod）。

### 7.4 风险
- 以上为静态分析结论，**需实机验证**（尤其：sprite=null 路径下 UI 是否有其他依赖、材质移植的 shader 是否正常加载）
- 新名要避开捏脸年龄变体命名（12岁X、10岁女X 等是自定义武将体系）
- 与其他替换同一武将的模组会冲突；Hero.json 覆盖为整条目级

### 7.5 全序列帧 CG（2026-09-24 二次补充：游戏原生支持，有现成范例）

**现状拆解确认**：身体动态 = MeshVertexVibration 609 点网格顶点动画（局部呼吸/摆动，非整体缩放）+ 眼部 = 512×512、3×3 图集由 shader `Custom/JU/SequenceFrame_Blink_PS_Correct` 自动播帧（_FPS=14、_PauseTime=3）。

**全序列帧范例：陈纪 / 陈纪2**（herocg 根目录仅有的两张 2000×2800 纹理）：
- `herocg/陈纪.png` = 2000×2800 = **2×2 帧**（每帧 1000×1400，四格为四个不同姿势，像素差 35–64%）
- `dynamiccg/windmaterial/陈纪.png` 同为 2000×2800 —— **RG 遮罩也按帧提供**（每帧一份）
- 同一个风场 shader `Custom/LeafWindSwing_Final_Smooth_EdgeFix` 兼容单图和 2×2 序列（检测图集长宽比）
- 陈纪风场材质关键参数（与单图 CG 差异）：_ScanTime=2.0、_EnableAlphaChannel=1、_PauseTime=1.0、_GammaConvertPower=2.0、_GammaAmplitudeBoost=1.6、_MaskThreshold=0.2、_G_MaskThreshold=0.05、_UVGrid=50、_EdgeSharp=4、_RootFix=0、_RootFalloff=1.2、_G_WindStrength=0、_G_Pseudo3D_Strength=0、_Pseudo3D_Strength=0、_G_DirAngle=0、_NoiseScale=1、_WindStrength=0.3；_MainTex 运行时注入（材质里 PathID=0）
- Data json 仍是 609 点（顶点呼吸叠加在序列帧之上）；眼部序列帧照常独立叠加

**模组全序列帧配方** = 7.2 的 icon 改名通道 + 陈纪格式：
1. 序列主图集 2000×2800（2×2 帧）+ RG 遮罩图集 2000×2800（每帧一份）
2. WindMaterial/<新名>.mat 按陈纪参数表配置，_MainTex/_MaskTex 指向图集
3. shader 用原版编译版（pathID 已定位：wind=-6920124991997196020，eyes=6371964938323802453）
4. Data/Eyes 照常；HeroCG 路径仍不放任何东西
- 帧数上限与布局规则（是否支持 4×4 等）由 shader 内部检测逻辑决定，2×2 为已验证安全格式；更大布局需实机测试或反编译 shader 的 DXBC 确认

### 7.6 眨眼图集规格普查（2026-09-24 三次补充）

全量扫描 1784 张眨眼图集 + 材质：
- **尺寸**：1783 张 512×512（3×3 帧每帧 ~170px），**唯一例外"孙谦"= 1024×1024**（每帧 ~341px）→ 尺寸**不强制**，shader 按纹理实际分辨率采样；自制图集可用 1024×1024 获得更清晰的眨眼（体积代价仅单文件 4 倍）
- **网格**：1769/1771 材质为 _Cols=3,_Rows=3（无一例外 3×3）；FPS 个别角色不同（14 为主，有 15/11 变体）→ 布局锁 3×3，帧率可调
- **眼区 Crop**：每角色不同（大乔 928,792,222×222；步练师 932,838,232×232；宝菓 912,792,236×236；女2 848,948,224×224），均在 2000×2800 素材系（X 左缘/Y 顶缘）
- **命名抽查**：大乔、步练师、宝菓、女2、陈纪图集均为 512×512
